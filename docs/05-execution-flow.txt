# §3 Execution Flow Reference

## §1 Goals and Use Cases
- Maintain at least 23% host CPU P95 over a rolling 7-day window so Oracle's Always Free reclaim guardrails never fire, while avoiding fragile manual tuning knobs. (§§1–2 of `docs/initial-implementation-plan.md`.)
- Default to Mode A (rootless, fair-share) but allow Mode B (rootful + best-effort `SCHED_IDLE`) to keep background shaping responsive without stealing CPU from real workloads. (§§2, 3.1.)
- Stay container-friendly: IMDSv2 supplies region/OCID metadata, Instance Principals read Monitoring metrics, and the controller adapts autonomously without console changes. (§§2–5.)

## §3 Runtime Wiring Overview
1. **CLI bootstrap (`cmd/shaper/entrypoint.go` + wiring helpers)** parses flags/YAML/env, builds the zap logger, and loads IMDS/OCI metadata. `entrypoint.go` only assembles the default run dependencies and hands control to `app.go`/`app_run.go` for orchestration and signal handling. `run_deps.go` owns exit codes and the factories for loggers, IMDS clients, controller creation, metrics exporters, and cgroup inspection. `logger_factory.go` builds the zap logger, `metadata_resolver.go` validates/resolves OCI metadata, `logging_metadata.go` records the resolved metadata for structured logs, `metrics_http.go` wires the metrics exporter/server, and `cgroup_inspection.go` records sandbox CPU limits. `controller_helpers.go` bridges CLI wiring to the adaptive controller without embedding controller logic in the entrypoint. The bootstrap then constructs the adaptive controller, estimator sampler, and worker pool before starting goroutines. (`run`, `defaultControllerFactory`, `buildAdaptiveController`.)
2. **Worker pool (`pkg/shape`)** spins `N` goroutines that run millisecond quanta, busy-spinning for the requested duty-cycle ratio and sleeping for the remainder. Rootful builds optionally downgrade each worker to `SCHED_IDLE`. (`Pool.Start`, `worker`.)
3. **Estimator sampler (`pkg/est`)** collects `/proc/stat` snapshots each second, computes host CPU utilisation deltas, and streams observations (or errors) to the adaptive controller. (`Sampler.Run`, `buildObservation`.)
4. **Adaptive controller (`pkg/adapt`)** runs the slow loop (default 1 h) that queries OCI Monitoring for 7-day P95 CPU. The ticker-driven orchestration (`AdaptiveController.Run`) drives the OCI step logic (`AdaptiveController.step`) while the estimator feedback path (`handleObservation`) clamps into min/max bounds and flips between normal/fallback/suppressed states based on host load feedback.
5. **Metrics and status HTTP handlers (`pkg/http/metrics`, `pkg/http/status`)** expose `/metrics` (OpenMetrics) plus `/healthz` so Prometheus and automation can scrape controller state, P95 readings, worker stats, and any recent OCI/estimator errors.

### §3.1 CLI Entrypoint boundaries
- `entrypoint.go`: builds `defaultRunDeps`, invokes the app runner, and leaves process exit handling isolated for tests.
- `run_deps.go`: defines exit codes and dependency factories (logger, IMDS, controller, metrics exporter/server, cgroup inspection) plus config/logging helpers.
- `bootstrap_args.go`/`bootstrap_config.go`/`bootstrap_metadata.go`/`bootstrap_metrics.go`/`bootstrap_controller.go`: stage CLI parsing/version printing, config/logging setup, metadata resolution, metrics bootstrap, and controller start sequencing.
- `app_bootstrap.go`: composes the bootstrap helpers to parse flags/YAML/env into runtime config, configure the logger, apply shutdown timers, and emit startup/config logs.
- `app_controller.go`: wires the staged metadata/metrics/controller bootstrap and exposes lifecycle helpers for starting/stopping the metrics server and controller.
- `app.go`/`app_run.go`: maintain the signal-aware run loop and compose the bootstrap/controller stages without re-embedding wiring logic.
- `controller_helpers.go`: converts runtime config into adaptive-controller inputs and keeps controller state machines out of the CLI.
- `metrics_client_default_*.go`: selects the metrics builder from `pkg/oci/metricsclient` (or the e2e shim) so the CLI only wires builders/offline paths.
- `metadata_resolver.go`: resolves IMDS/OCI metadata for runtime config and validates controller prerequisites.
- `logger_factory.go`: constructs zap loggers with the configured level and encoder settings. IMDS HTTP

## §5 Package Touchpoints
- `pkg/oci`: Instance-principal Monitoring client issues the MQL percentile query and paginates results, returning the freshest datapoint. (`Client.QueryP95CPU`.)
- `pkg/oci/metricsclient`: Builds/wraps metrics clients, exposes context helpers for dependency injection, and surfaces the instance-principal wrapper used by the CLI defaults.
- `pkg/imds`: HTTP client reads region, compartment OCID, and instance ID with retried IMDSv2 requests; CLI falls back to offline overrides when needed.
- `pkg/adapt`: State machine tracks `normal`, `fallback`, and `suppressed`, records errors for `/healthz`, and surfaces target/mode/state for `/metrics`.
- `pkg/est`: Publishes host utilisation plus the last sampling error so suppression hysteresis keeps the shaper out of the way when the host is busy.
- `pkg/shape`: Worker pool honours controller targets immediately so increases/decreases to the duty cycle reflect the latest OCI feedback.
